## 1. 공통 규칙

### 1-1. 시간·움직임 값 (CSS 변수로 한곳에)

`style.css` 맨 끝 "2026-11 디자인 개편" 층 다음에 "애니메이션" 층을 새로 만들고 값을 모은다.

```css
:root {
  --dur-1: 120ms;  /* 색·누름 같은 아주 작은 변화 */
  --dur-2: 180ms;  /* 본문 들어오기·토스트·펼치기 */
  --dur-3: 240ms;  /* 대화상자·플레이어·지도 */
  --ease-out: cubic-bezier(.2, .8, .2, 1);   /* 들어올 때: 빠르게 시작, 부드럽게 멈춤 */
  --ease-in: cubic-bezier(.4, 0, 1, 1);      /* 나갈 때 */
  --ease-std: cubic-bezier(.4, 0, .2, 1);    /* 색·크기처럼 제자리 변화 */
  --rise: 6px;     /* 들어올 때 이동 거리 */
}
```

- **"택티컬 HUD" 디자인에 맞게 짧고 단단하게.** 튕기는(bounce) 효과, 0.3초 넘는 이동은 쓰지 않는다.
- 나갈 때는 들어올 때의 70% 정도로 더 짧게(사람은 사라지는 것을 오래 기다리지 않는다).
- 움직이는 것은 `transform`(이동·크기)과 `opacity`(투명도)만. `height`·`width`·`top`·`margin` 은 애니메이션하지 않는다(휴대폰에서 끊김).

### 1-2. "사용자가 바꿨을 때만" 움직인다 (가장 중요)

이 사이트는 `render()`(`site/assets/app.js:430`)가 `app.innerHTML` 을 통째로 바꾼다. 그런데 `render()` 는 사용자가 탭을 누를 때뿐 아니라 **5분 데이터 확인, 방송 상태(2분), 실시간 점수(10초), 홈 카운트다운** 같은 주기적 갱신에서도 불린다.
그대로 "다시 그릴 때마다 애니메이션"을 넣으면 경기 중 10초마다 화면이 깜빡인다.

그래서:

- `hashchange` 처리(`app.js:3636`)와 사용자 클릭(보기 모드 `setMode`, 응원 팀 `setMain`/`toggleFav`, 스포일러 `reveal`, POI 크게 보기)에서만 한 번 쓰는 표시 `navAnim = 'page' | 'sub' | 'soft'` 를 세운다.
- `render()` 는 `app.innerHTML = html` 바로 뒤(`app.js:458`)에 그 표시가 있을 때만 `#app` 에 클래스(`anim-page` 등)를 붙이고 표시를 지운다. 애니메이션이 끝나면(`animationend`) 클래스를 뗀다.
- 주기적 갱신은 지금처럼 "같으면 안 그림", 순위 탭은 "바뀐 조각만 바꿈"(`patchApp`)을 그대로 쓰고, 화면 전체 애니메이션은 **절대 안 붙인다.** 바뀐 값 강조만 따로(4-1).

| 표시 | 언제 | 효과 |
|---|---|---|
| `page` | 주 메뉴 탭이 바뀜(`navTab !== lastNav`) | 1-3 의 "본문 들어오기" |
| `sub` | 같은 탭 안에서 주소만 바뀜(세부 메뉴, 지역·경기, 팀 상세 → 다른 팀) | 투명도만 0.4→1, 150ms (움직임 없음) |
| `soft` | 보기 모드·응원 팀·스포일러 등 같은 주소에서 내용이 바뀜 | 투명도만 0.6→1, 120ms |

### 1-3. 기술상 주의 (이 저장소에서 실제로 걸리는 것)

- **헤더(`.top`)와 메뉴(`.tabbar`)에는 `transform`·`filter` 를 쓰지 않는다.** 휴대폰 아래 고정 메뉴의 기준이 헤더로 바뀌어 메뉴가 사라진다(`style.css:1442` 주석). 메뉴 효과는 안쪽 요소나 `::before` 에만.
- **`#app` 자체에도 `transform` 을 걸지 않는다.** `#app` 안에 있는 방송 플레이어의 미니 플레이어·시네마 모드가 `position: fixed` 라서, 조상에 `transform` 이 있으면 화면 고정이 풀린다. 이동 효과는 `#app` 의 자식(`.ph`, `.subtabs`, 첫 `section` 몇 개)에만 걸고, `#lvPlayer` 를 품은 구역은 투명도만 쓴다. `animation-fill-mode` 는 `none`(끝나면 transform 이 남지 않게).
- 고정 선택줄(`.st-stick`, `position: sticky`)은 자식이 아니라 줄 전체를 움직이지 않는다. 선택줄은 그대로 두고 그 아래 본문만 바꾼다(지금의 "스크롤 위치 유지" `keepY` 도 그대로).
- 방송 `iframe` 은 움직이거나 다른 곳으로 옮기지 않는다(옮기면 방송이 끊긴다). 감싸는 상자의 투명도·위치만 바꾼다.

## 2. 상황별 효과

### 2-1. 주 메뉴 탭 전환 (순서 1)

대상: 헤더 `.tabbar a` 7개, 휴대폰 하단 고정 / PC 한 줄.

- **본문 들어오기** (`anim-page`): `.ph`(제목 머리), `.subtabs`, 본문 첫 3개 구역에
  `opacity 0→1` + `translateY(var(--rise))→0`, `--dur-2`, `--ease-out`.
  차례로 30ms 씩 늦춰(`.ph` 0ms, `.subtabs` 30ms, 첫 구역 60ms, 둘째 90ms) 위에서 아래로 흐르게. **4번째 구역부터는 효과 없음**(표가 긴 화면에서 수백 개를 움직이지 않게).
- **제목 빗금(/) 강조**: `.ph` 의 제목에 `clip-path: inset(0 100% 0 0) → inset(0 0 0 0)` 으로 왼쪽에서 오른쪽으로 그려지는 효과, 220ms. HUD 느낌을 살리는 한 가지 포인트(요소가 작아 비용이 적다).
- **메뉴 선택 표시**
  - 휴대폰: 위쪽 2px 빨간 선(`.tabbar a[aria-current='page']::before`)이 가운데에서 양옆으로 펼쳐짐 `scaleX(0→1)`, `--dur-2`. 아이콘 색은 `color` 전환 `--dur-1`.
  - PC: 선택 배경 + 아래 2px 선(`box-shadow`)을 `background-color`·`box-shadow` 전환 `--dur-1`. (선이 옆 탭으로 미끄러지는 효과는 위치 계산이 필요해 3단계 선택 사항.)
  - 누를 때: 아이콘 `scale(.92)` 100ms(`:active`, 휴대폰 손가락 반응).
- 스크롤: 지금처럼 맨 위로 바로 이동(`scrollTo(0, …)`). 부드러운 스크롤은 쓰지 않는다(긴 화면에서 늦게 느껴짐).

### 2-2. 세부 메뉴·선택 버튼 (순서 1)

대상: 알약형 세부 메뉴(`.subtabs a`), 지역·경기·지도 선택(`.seg a`, `.seg button`), 보기 모드(`.mode-seg`), LCQ 경기 탭(`.lcq-tabs`), 팀 탭 정렬.

- 선택 표시: `background-color`·`color`·`border-color` 전환 `--dur-1`, `--ease-std`. (지금은 즉시 바뀜)
- 본문: `anim-sub` — 투명도만 0.4→1, 150ms. 위치 이동 없음(같은 탭 안에서 자꾸 움직이면 어지럽다).
- 가로로 넘치는 줄에서 고른 항목이 화면 밖일 때 미는 동작(`render()` 의 `scrollLeft` 맞춤, `stickInit`)은 `scrollTo({ left, behavior: 'smooth' })` 로 바꾼다(움직임 줄이기 설정에서는 즉시).
- 순위 탭 선택줄(`.st-stick`)은 2-1 과 달리 **선택줄은 가만히**, 아래 본문만 `anim-sub`.

### 2-3. 대화상자: 설정·제보 (순서 1)

대상: `index.html` 의 `<dialog id="settings">`, `<dialog id="feedback">` (`showModal()`, `app.js:156`, `app.js:3414`).

- 열기: 창 `opacity 0→1` + `scale(.96)→1` + `translateY(8px)→0`, `--dur-3`, `--ease-out`. 뒷배경(`::backdrop`) `opacity 0→1`, 같은 시간.
- 휴대폰(폭 600px 미만): 위 대신 **아래에서 올라오는 시트** 느낌 `translateY(24px)→0` 도 후보(운영자 선택).
- 닫기: `opacity 1→0` + `scale(.98)`, 140ms, `--ease-in`.
- 구현: `@starting-style` + `transition-behavior: allow-discrete`(`display`·`overlay` 도 전환 목록에). 지원 안 하는 브라우저(오래된 Safari 등)는 지금처럼 바로 열리고 닫힌다 — 별도 JS 없이 자연스럽게 빠진다.

### 2-4. 토스트 (순서 1)

대상: `.toast`(`app.js:370`, `style.css:1416`). 지금은 `hidden` 속성으로 즉시 보임/숨김.

- 나타남: `opacity 0→1` + `translate(-50%, 8px)→translate(-50%, 0)`, 180ms.
- 사라짐: `opacity 1→0`, 160ms 뒤 `hidden`.
- `hidden` 을 바로 토글하지 말고 `.show` 클래스를 붙였다 떼고, 사라짐 전환이 끝난 뒤(`transitionend` 또는 200ms 타이머) `hidden` 을 건다. 휴대폰 하단 메뉴 위 위치는 그대로.

### 2-5. 펼치기·접기 (순서 1)

대상:
- 순위·포인트 표의 줄 누르면 열리는 내역(`[data-toggle]`, `app.js:3348`, 대상 `hidden` 토글)
- `<details>`: `details.lz`, `details.fold`, `details.past`, `details.refresh-note`, 경기 카드 안 `details`
- "더 보기": 팀 목록 `.team-group.clip`(`data-unclip`), 이전 결과 더 보기(`.more-days` → `#schMore`), 로스터 변경 40건 이후

효과:
- 열린 내용: `opacity 0→1` + `translateY(-4px)→0`, `--dur-2`. 높이는 애니메이션하지 않는다(표 내역은 수십 줄이라 높이 애니메이션이 휴대폰에서 끊김).
- 펼침 화살표·"자세히" 표시가 있으면 `rotate(0→90deg)` 또는 `180deg`, `--dur-1`.
- `<details>` 는 최신 Chrome(131+)에서 `::details-content` + `interpolate-size: allow-keywords` 로 높이 전환이 가능하지만, **작은 것(`refresh-note` 같은 설명 글)에만** 쓰고 표 내역에는 쓰지 않는다. 지원 안 하면 바로 열린다.
- "더 보기"로 새로 보이는 팀 카드: 묶음 전체에 투명도 0→1, 200ms (카드마다 따로 늦추지 않음).

### 2-6. '내 팀으로 이동'·CP 순위 이동 강조 (이미 있음, 맞추기만)

- '내 팀으로 이동'(`app.js:1881`)은 `tr.flash td` 에 테두리(outline)가 1.6s 동안 사라지는 효과(`stFlash`)가 이미 있다.
- 포인트 표에서 팀으로 이동할 때는 `tr.jumped > td` 배경 강조(`cpJump`, 2s)가 이미 있고 움직임 줄이기도 처리돼 있다.
- 바꿀 것: 두 효과의 길이·색을 하나로 맞춘다. 테두리만으로는 휴대폰에서 잘 안 보이므로 `.flash` 에도 `cpJump` 처럼 배경 강조를 더하는 것을 권한다(1.2~1.6s, 한 번). 새로 만드는 실시간 값 강조(2-7 `.upd`)도 같은 색 규칙을 쓴다.

### 2-7. 실시간 점수·순위 갱신 강조 (순서 2)

대상: 순위 탭의 부분 갱신(`patchApp`, `app.js:402`), 경기 중 점수창, 게임별 점수 열(g1…g6), 진행 그림의 'N매치 진행 중'.

- `patchApp` 이 바꾼 조각(`ops`)에만 `.upd` 클래스: 배경 `var(--apex)` 15% → 투명, 900ms. 숫자가 오른 칸이면 청록(`--cyan`), 내린 칸이면 회색으로 구분하는 것도 후보.
- 순위 화살표(▲▼, `.mv`)가 새로 생기면 `scale(1.3)→1`, 200ms.
- **하지 않을 것**: 줄 순서가 바뀔 때 줄이 미끄러져 자리 바꾸는 효과(FLIP). 표 전체를 다시 계산해야 하고 20~40줄을 동시에 움직이면 휴대폰에서 끊긴다. 나중에 결승 표(20줄)만 따로 시험해 볼 수 있다.
- 한 번에 바뀐 칸이 많으면(예: 20칸 초과, 게임이 끝나 표 전체가 바뀔 때) 강조를 생략한다(화면 전체가 번쩍이면 의미가 없다).

### 2-8. 방송 플레이어 (순서 2)

대상: `#lvPlayer`(`playLive` `app.js:3136`, `lvMini` `app.js:3116`, `lvCinema` `app.js:3106`), 방송 카드 `button.lv-card`.

- 처음 열 때: 플레이어 상자 `opacity 0→1`, `--dur-3`. iframe 이 로드되기 전 검은 바탕에 은은한 깜빡임(skeleton)은 선택.
- 멀티뷰 화면 추가: 새 칸(`.lv-tile`) `opacity 0→1` + `scale(.97)→1`, 180ms. 닫을 때는 즉시(재생 중인 iframe 을 흐리게 남겨 둘 이유 없음).
- **미니 플레이어로 바뀔 때**(휴대폰·태블릿, 스크롤로 자리가 지나감): 오른쪽 아래에 `translateY(16px)→0` + `opacity 0→1`, 220ms. 이때 transform 은 고정된 상자 자신에만 걸리므로 괜찮다. 원래 자리로 돌아갈 때는 효과 없이(이미 부드러운 스크롤이 있다).
- 시네마 모드: 검은 바탕이 `opacity 0→1`, 200ms. 화면을 키우는 확대 효과는 iframe 크기 재계산이 매 프레임 일어나 쓰지 않는다.
- 방송 카드: 2-12.

### 2-9. POI 드래프트 지도 (순서 2)

대상: `poiSection`(`app.js:1777`), 핀 `.poi-pin`, 툴팁 `.poi-tip`(`style.css:748`, 지금 `display:none↔flex`), 크게 보기(`data-poi-zoom`).

- 지도·로비·경기 바꿈: 바탕 그림 `opacity 0→1`, 220ms. 그 뒤 팀 핀이 고른 순서대로 `scale(.6)→1` + `opacity`, 각 180ms, 15ms 간격(20팀이면 마지막 핀이 약 0.5초). 드래프트가 진행되는 순서가 보이는 효과.
- **실시간으로 새 핀이 생길 때**(`poiTick` 이 진행 중 드래프트를 받아 핀을 더함): 새로 생긴 핀만 `scale(1.4)→1` + 테두리 빛남 600ms. 이미 있던 핀은 움직이지 않는다. 순위 탭 부분 갱신과 같은 원리로 "새로 생긴 것"만.
- 툴팁: `display` 대신 `opacity`·`visibility` + `translate(-50%, 4px)→translate(-50%, 0)`, 120ms. 마우스를 떼면 80ms 로 사라짐.
- 핀 강조(`.hl`, 표 줄과 연결)는 이미 `transform .12s` 가 있음. 그대로.
- 크게 보기 전환: 지금은 `render()` 로 다시 그림. `anim-soft`(투명도만)로 충분.

### 2-10. 스포일러 가림 풀기 (순서 2)

대상: `.spoil-box` / `.spoil-hidden`(`style.css:616`, 지금 `blur(9px)`), `reveal()`(`app.js:134`, 누르면 `render()` 로 다시 그림).

- `reveal()` 이 다시 그리기 전에 그 대회 키를 `justRevealed` 에 적어 두고, 다시 그린 뒤 그 내용 상자에 `.reveal-in` 을 붙인다: `filter: blur(6px)→0` + `opacity .55→1`, 300ms.
- blur 는 비싼 효과라 **이 한 상자에만, 한 번만.** 상자가 화면보다 크면 blur 없이 투명도만.

### 2-11. 보기 모드·대표 응원 팀 바꿈 (순서 2)

대상: 보기 모드(`setMode`, `app.js:65`: 한국 관련 / APAC North / 내 응원 팀), 대표 팀(`setMain`, `app.js:76`, `applyTeamTheme` 이 `--apex` 를 팀 색으로 덮음), 관심 팀 칩(`toggleFav`, `.fav-chip`).

- 내용: `anim-soft`(투명도 0.6→1, 120ms). 목록 순서가 바뀌는 것을 움직임으로 보여 주지는 않는다.
- 강조색(`--apex`)이 팀 색으로 바뀌는 것: **색을 서서히 바꾸지 않는다.** CSS 변수 색을 전환하려면 `@property` 로 등록해야 하고, 사이트 전체가 이 변수를 쓰므로 매 프레임 모든 요소 스타일을 다시 계산한다(휴대폰에서 끊김). 대신 헤더 팀 칩(`#brandTeam`)이 `scale(.8)→1` + `opacity` 로 톡 나타남, 200ms.
- 관심 팀 칩을 누를 때: 칩 `scale(.94)` 누름 + 선택 체크 표시 `scale(1.2)→1`, 150ms.

### 2-12. 카드 누름·마우스 올림 (순서 3)

대상: 방송 카드(`.lv-card`), 팀 카드(`.tile`), 영상(`.vid`), 경기 카드(`.match`), 규칙 카드(`.rule-card`), 홈 "다음 경기" 카드(`.nx`).

- 누를 때(`:active`): `scale(.98)`, 80ms. 휴대폰 손가락 반응용.
- 썸네일 그림 투명도 변화(`.lv-card:hover .lv-thumb img`)에 `transition: opacity var(--dur-2)` 를 붙인다(지금은 즉시).

### 2-13. 밝은↔어두운 모드 (순서 3)

## 3. 움직임 줄이기 (`prefers-reduced-motion`)

기기 설정에서 "동작 줄이기"를 켠 사람(멀미·전정 장애 등)을 위한 규칙.

- 이동(`translate`)·크기(`scale`)·회전·clip 효과는 **모두 끈다.**
- 투명도 변화는 남기되 100ms 이하로 줄인다(정보가 바뀌었다는 신호는 남긴다). 색 강조(`.flash`, `.jumped`, `.upd`)는 남긴다(지금 `.jumped` 처럼 깜빡임 대신 옅은 배경을 잠시 유지).
- 반복 애니메이션(LIVE 점)은 이미 꺼져 있다. 새로 넣는 것도 같게.
- JS: 부드러운 스크롤(`behavior: 'smooth'`)은 지금처럼 `'auto'`, `startViewTransition` 은 건너뛴다. 핀 차례 등장(stagger)도 한 번에.
- 구현은 효과를 `@media (prefers-reduced-motion: no-preference) { … }` 안에만 넣는 방식(지금 `style.css:186` 과 같은 방식)으로 한다. "다 넣고 reduce 에서 끄기" 보다 빠뜨릴 위험이 적다.
- **설정 창에 "애니메이션 줄이기" 스위치**(선택): 기기 설정과 별개로 켤 수 있게 `html.no-motion` 을 두고 `localStorage('algskr.motion')` 에 저장. CSS 는 `@media (prefers-reduced-motion: no-preference) { :root:not(.no-motion) … }` 로 쓴다. 운영자 결정 필요.

## 4. 휴대폰 성능

운영자와 방문자 대부분이 휴대폰이라 가장 신경 쓸 부분.

1. **`transform`·`opacity` 만 움직인다.** 이 둘은 화면 합성 단계에서만 처리돼 끊기지 않는다. `height`·`width`·`top`·`box-shadow`·`filter` 애니메이션은 쓰지 않는다(예외: 스포일러 blur 한 상자, `.flash` 배경색).
2. **움직이는 요소 수 제한**: 탭 전환은 위쪽 3~4개 구역만, 표 줄 하나하나는 절대 움직이지 않는다(순위·포인트 표는 수백 줄). 핀은 최대 20~40개.
3. **`will-change` 를 계속 걸어 두지 않는다.** 필요하면 애니메이션 중에만(클래스가 붙어 있는 동안). 계속 걸면 휴대폰 메모리를 차지한다.
4. **주기적 갱신에는 화면 전체 효과 금지**(1-2). 실시간 점수(10초)·방송(2분)·데이터(5분) 갱신이 애니메이션을 부르면 배터리와 발열이 늘고 화면이 깜빡인다.
5. **어두운 모드 헤더는 `backdrop-filter: blur(12px)`** (`style.css` 구조 개편 ①). 헤더 바로 아래에서 큰 면적이 움직이면 blur 를 매 프레임 다시 계산한다. 그래서 이동 거리를 6px 로 작게 두고, 시간도 200ms 안쪽.
6. **애니메이션이 끝나면 클래스를 떼어** transform 이 남지 않게 한다(고정 위치·`sticky` 문제 예방, 다음 전환 때 다시 시작 가능).
7. 누른 뒤 화면이 바뀌기까지 기다리게 하지 않는다: 내용은 즉시 바꾸고 효과는 그 위에 얹는다(사용자가 누른 순간 반응).
8. 저사양 기기 대비(선택): `navigator.hardwareConcurrency <= 4` 또는 `navigator.connection?.saveData` 면 차례 등장(stagger)을 끄고 투명도만.

## 5. 구현 순서와 확인 방법

**1단계** (CSS 위주, 위험 적음): 공통 변수, 주 메뉴·세부 메뉴 전환(`navAnim`), 대화상자, 토스트, 펼치기, 강조 효과 맞춤(2-6), 움직임 줄이기 규칙.
**2단계** (실시간 갱신과 얽힘): 바뀐 값 강조(`patchApp`), 방송 플레이어·미니 플레이어, POI 지도·핀, 스포일러, 보기 모드·응원 팀.
**3단계** (선택): 카드 hover, 테마 전환 View Transition, PC 메뉴 밑줄 미끄러짐, 설정 창 "애니메이션 줄이기".

확인(CLAUDE.md "검증 습관" 기준):
- Playwright 로 휴대폰 320·390, PC 1280·1440 / 한·영·일. 전체 화면 오류 점검 35개 경로.
- **데이터 로직은 바꾸지 않으므로** 바꾸기 전후 모든 화면 HTML 이 같은지 대조(애니메이션 클래스는 `render()` 뒤에 붙으므로 `html` 문자열은 같아야 한다).
- `page.emulateMedia({ reducedMotion: 'reduce' })` 로 움직임 줄이기 확인.
- 주기적 갱신 중 애니메이션이 안 붙는지: 같은 주소에서 `render()` 를 여러 번 불러 `#app` 에 `anim-*` 클래스가 생기지 않는지 시험.
- 휴대폰 성능: Chrome 개발자 도구 CPU 4배 느리게 + 성능 기록으로 탭 전환·순위 표 갱신 때 16ms 넘는 프레임이 없는지.
- 하단 고정 메뉴가 전환 중에도 제자리에 있는지(헤더 transform 금지 규칙), 미니 플레이어·시네마 모드가 탭 전환 직후에도 화면에 고정되는지.

## 6. 정한 것 (2026-11-20, 운영자: 권장안으로)

1. 설정·제보 창은 **가운데 창**(살짝 커지며 나타남). 휴대폰 아래 시트는 쓰지 않는다.
2. 실시간 점수 강조는 **강조색 한 가지**(`--apex`, 대표 응원 팀을 고르면 팀 색). 기존 CP 이동 강조(`cpJump`)와 같은 규칙.
3. 설정 창에 **"애니메이션 줄이기" 스위치**를 둔다(`#optMotion`, `localStorage('algskr.motion') = 'off'` → `html.no-motion`, `index.html` 머리 스크립트가 처음부터 적용).

## 7. 구현 메모

- 움직임 규칙은 모두 `@media (prefers-reduced-motion: no-preference)` 안 + `:root:not(.no-motion)` 조건. 색 강조(`.flash`, `.jumped`, `.upd`)만 그 밖에 있다.
- 움직임 줄이기에서는 투명도 변화도 끈다(3절의 "100ms 이하로 남김"보다 단순하게).
- `translate`·`scale` 개별 속성을 써서 기존 `transform`(POI 핀 위치, 토스트 가운데 맞춤, 툴팁 방향)과 겹치지 않게 했다.
- POI 핀 차례 등장은 핀에 `--i`(순서) 인라인 스타일을 붙인다. 화면 HTML 비교 때는 이 값을 빼고 비교한다.
- 밝은↔어두운 모드는 `document.startViewTransition` 이 있을 때만 교차 전환.
- 실제 대회에서 확인할 것: 진행 중 POI 드래프트의 새 핀 강조(`pin-new`), 실시간 점수 칸 강조(`upd`), 미니 플레이어 등장(작업 공간에서는 방송 API 에 접속이 안 돼 시험 못 함).
